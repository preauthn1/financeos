## 三、环境搭建

### 3.1 环境要求

- PHP >= 8.1，扩展：`pdo_mysql`、`redis`、`mbstring`、`json`、`openssl`
- Composer 2.x
- MySQL >= 8.0
- Redis >= 7.0
- Node.js >= 18，pnpm

### 3.2 后端启动

```bash
# 安装依赖
composer install

# 配置环境
cp .env.example .env
# 编辑 .env：DB_*、REDIS_*、JWT_SECRET

# 创建数据库
mysql -u root -p -e "CREATE DATABASE webman_admin CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 根据 Model tableSchema 同步表结构（主迁移方式）
php webman model

# 填充初始数据
php database/seed.php

# 同步菜单权限
php webman menu --fresh

# 启动（Windows）
php windows.php

# 启动（Linux）
php start.php start
```

默认监听：`http://127.0.0.1:8787`

### 3.3 管理后台前端

```bash
cd frontend
pnpm install

# frontend/.env.development
# VITE_API_BASE_PATH=http://127.0.0.1:8787

pnpm dev
```

默认开发端口：`http://127.0.0.1:4000`（见 `frontend/vite.config.ts`）

### 3.4 H5 前端

```bash
cd web
pnpm install

# web/.env
# VITE_API_BASE_URL=http://127.0.0.1:8787/

pnpm dev
```

默认开发端口：`http://127.0.0.1:3000`（见 `web/vite.config.js`）

## 四、架构分层

```
Request → Middleware → Controller → Service → Model → MySQL/Redis
```

| 层级 | 职责 | 命名 |
|------|------|------|
| Controller | 参数接收、调用 Service、返回 JSON | `XxxController` |
| Service | 业务逻辑、事务、异常 | `XxxService` |
| Model | 表映射、关联、Schema 定义 | `XxxModel` |
| Middleware | 认证、权限、日志、CORS | `XxxMiddleware` |

### 4.1 全局中间件

所有请求先经过 `config/middleware.php` 中注册的全局中间件：

```
CorsMiddleware → LocaleMiddleware
```

### 4.2 管理后台请求链路

```
全局中间件 → IpWhitelistMiddleware → AuthMiddleware → AdminLogMiddleware → Controller
```

### 4.3 会员 API 请求链路

```
全局中间件 → MemberAuthMiddleware（按路由挂载，部分接口为 OptionalMemberAuthMiddleware）→ Controller
```

## 五、编码规范

### 5.1 PHP

- 遵循 PSR-12
- 文件顶部 `declare(strict_types=1);`
- 控制器只做参数校验与响应，业务放 Service
- 模型使用 `DefinesTableSchema` trait 定义 `tableSchema()`

### 5.2 Vue（管理后台）

- Composition API + `<script setup>`
- 组件 PascalCase
- API 请求统一放 `src/api/`
- 权限按钮使用 `v-permission="'slug'"`

### 5.3 接口约定

**成功响应：**

```json
{ "code": 200, "msg": "success", "data": {} }
```

**失败响应：**

```json
{ "code": 42201, "msg": "错误描述", "data": null }
```

**认证：**

```
Authorization: Bearer <access_token>
```

- 管理后台 Token：`guard` 为管理员身份，由 `/admin/login` 签发
- 会员 H5 Token：`guard` 必须为 `member`，由 `/api/login/doLogin` 签发；失效时返回 `code: 10001`

## 七、新增功能开发流程

### 7.1 后端

1. 在 `config/routes/admin.php` 或 `config/routes/api.php` 定义路由
2. 创建 `Controller`，实现静态方法 `menuConfig()` 声明菜单与 API 权限
3. 创建 `Service` 实现业务逻辑
4. 创建/更新 `Model`，定义 `tableSchema()`
5. 执行 `php webman model` 同步表结构
6. 执行 `php webman menu --fresh` 同步权限

### 7.2 管理前端

1. 在 `src/api/` 添加 API 封装
2. 在 `src/views/` 创建页面
3. 在路由配置中注册页面
4. 按钮添加 `v-permission`

### 7.3 H5

1. 在 `web/src/api/` 添加或扩展接口（主入口为 `home.js` 中的 `AuthService`）
2. 在 `web/src/view/` 创建/修改页面
3. 在路由中注册页面

## 十、Redis 用途

| 用途 | Key 示例 |
|------|----------|
| 权限缓存 | 管理员权限集合 |
| 匹配锁 | `finance_product_match_lock:{user_id}:{level_id}` |
| 匹配结果 | `maestro:{user_id}_{level_id}_match_status` |
| 登录锁定 | 失败次数统计 |
| Token 黑名单 | JWT 注销 |
| 设置缓存 | `setting:{key}`（如 `setting:finance_product_data`） |
| 队列 | 队列名 `finance_product_match`（消费者 `FinanceProductMatchConsumer`） |

## 十一、队列

广告位匹配使用 Redis 异步队列：

```
队列名: finance_product_match
  ← ApiFinanceProductService::validateAndQueue() 投递
  → FinanceProductMatchConsumer::consume()
  → FinanceProductMatchService::execute()
  → ApiFinanceProductService::storeMatchPayload() 写入 Redis
  ← H5 轮询 GET /api/finance_product/get_finance_product_order
```

## 十五、常见问题

### Q: 管理后台接口 403？

检查角色是否分配对应 API 权限，执行 `php webman menu --fresh` 后重新分配。

### Q: 广告位配置页 500？

检查 Service 中 Model 的 `use` 导入是否完整。

### Q: 匹配无响应？

确认 Redis 队列消费者已启动（Webman 内置进程），检查 `finance_product_match_lock` 是否残留。

### Q: 弹窗超出可视区域？

管理后台弹窗添加 `modal-class="admin-scroll-dialog-wrap"`（样式见 `frontend/src/styles/admin-ref-theme.less`）。
